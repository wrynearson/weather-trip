Design brief

Trip Weather Planner

Working prototype (Trip Weather Planner.dc.html) handed off for production build. This brief covers intent, visual system, states, and behavior — read alongside the prototype, which is the source of truth for exact spacing/copy.

1. What it does

A single-page tool for checking expected weather across a multi-city trip. The user adds stops (city + date range), sees typical high/low/rain-chance per stop, and an overview card summarizing the trip's low/high, general character (sunny / mixed / rainy), and a range chart across all stops.

Max 1–2 background tones; everything else is neutral + the single accent. Don't introduce new hues without checking against this palette.

Type

  • UI text: Helvetica Neue / Helvetica / Arial, sans-serif.
  • Numeric data (temperatures, counts, dates in the trend tooltip): IBM Plex Mono, tabular numerals — always monospace so columns of numbers align.
  • Scale: page title 22px/600 · stat values 27–30px/500 mono · stop city name 17px/600 · body 13–14px · eyebrow labels 10.5–12px uppercase, tracked +0.05–0.11em, color #8A837B.

Shape & spacing

  • Content column: 780px max-width, centered.
  • Card radius 12–14px; pill/badge radius 999px; input & button radius 8–9px.
  • Cards: 1px border + very soft shadow (0 1px 2px rgba(28,25,23,.04)); the sticky summary card and open editors get a stronger shadow to read as "elevated."
  • No SVG hand-drawn illustration — icons are simple geometric marks (circles/rounded rects) only, consistent with the condition icon set already in the prototype.

3. Layout & components

Header

Title + one-line subtitle, left. Right-aligned: °C/°F segmented toggle, "Clear trip" (text link, only once stops exist), and an "i" About button (circular, opens a modal — see §5). Keep the subtitle as the single source of the "these are historical averages" disclaimer; don't duplicate it elsewhere.

Trip summary card

Sticky card at the top of the list, appears once ≥1 stop has loaded. Left-to-right: condition badge (Generally sunny / Mixed conditions / Mostly rainy, computed from average rain% across stops), then Trip low and Trip high stat pairs — all three top-aligned. Right: stop count. Below, once ≥2 stops: a range chart (absolute range band, avg min/max band, avg line, per-stop condition icons and city labels on the axis, hover/touch tooltip with avg + record range + rain chance for the nearest day).

Trip stops list

Collapsible section ("Trip stops" header with Hide/Show). Each stop is a numbered card with three mutually exclusive states:

StateTriggerShows
LoadingJust added/edited, fetch in flightShimmer placeholders over the stat grid, "looking up averages…"
ReadyData resolvedCity, condition icon, nights + date range, region, source tag (Forecast · Nd out / Historical avg), typical high/low/rain%, edit button
EditingUser opened it, or the trailing "new stop" rowLocation (autocomplete), date, nights fields; Cancel / Save; Delete stop (existing only)

Trailing "+ Add stop" row when not editing; empty state (no stops) is a centered dashed card with a single "Add your first stop" CTA. When the list is collapsed, a one-line hint replaces it ("N stops hidden — showing trip overview only").

About modal

Opened from the header "i" button. Centered dialog over a scrim; click-outside or × closes it. Content: what the figures represent (historical averages, not forecast; near-term stops may blend forecast data) and a privacy note (trip saved locally only, not synced).

4. Interaction notes

  • Units: °C/°F toggle affects every temperature on the page instantly; persisted with the trip.
  • Autocomplete: typing in Location filters a fixed city list by name-prefix or region-prefix, top 6 shown; Enter picks the top match, Escape cancels the editor.
  • Adding a stop: new stop's default date auto-continues from the previous stop's date + nights, so a multi-city itinerary chains without re-typing dates.
  • Chart: hover (desktop) or drag (touch) scrubs a vertical guide + tooltip showing the nearest stop's date-level detail.
  • Persistence: stops + units saved to localStorage only — no account/sync.

5. Data & logic — prototype vs. production

The prototype fakes climate data so the UI can be evaluated without a live API. Production needs to swap this for a real source — the pieces below map roughly 1:1 to what a real backend should provide.

  • City list: prototype ships ~60 hardcoded cities with a name/region and a hand-tuned annual temperature curve + rainfall curve. Production needs a real geocoding/city-search endpoint.
  • Climate model: a single cosine curve per city approximates seasonal high/low/rain%. Production should call a historical-climate-normals API keyed by lat/lon + day-of-year.
  • Forecast vs. historical split: stops within 15 days out are labeled "Forecast · Nd out" (small deterministic jitter added on top of the climate baseline to simulate real forecast data); anything further out is labeled "Historical avg." Production should use this same threshold to decide whether to call a short-range forecast API or fall back to the historical-normals API.
  • Condition classification: sunny/partly/cloudy/rainy/snowy is derived purely from rain% (and freezing high, for snow) — no cloud-cover or wind data. Fine as a placeholder; revisit if a richer data source is wired in.

6. Edge cases to preserve

  • 1 stop: no trend chart (needs ≥2 to be meaningful); summary card still shows low/high/badge.
  • Long city names truncate with an ellipsis on the chart axis only, never in the stop card.
  • Save button disables until both a city and a date are chosen; inline hint text tells the user what's missing.
  • Removing the stop currently being edited closes its editor.

7. Open questions for engineering

  • Real geocoding/city-search API — which provider, and does it return the region label format used here ("United Kingdom", "Türkiye", etc.)?
  • Climate-normals + short-range forecast data sources, and rate limits for a client-side search-as-you-type flow.
  • Should trips ever sync across devices, or is local-only persistence the intended final behavior?
